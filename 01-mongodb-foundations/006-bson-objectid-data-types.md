# Lesson 006 — BSON, ObjectId and MongoDB Data Types

## 1. JSON vs BSON
**JSON** is a text data format. **BSON** (Binary JSON) is the binary representation MongoDB uses for documents, supporting additional types such as ObjectId, Date, and Decimal128.

```text
JavaScript object → MongoDB driver serialization → BSON document → MongoDB storage
```
JSON-like syntax in mongosh is a convenient way to write documents, but the stored representation is BSON.

## 2. Common BSON types
| Type | Example in mongosh | Typical use |
| --- | --- | --- |
| String | `"Asha"` | Names |
| Boolean | `true` | Flags |
| Int32 | `NumberInt(25)` | Small integers |
| Int64 | `NumberLong("9000000000")` | Large integers |
| Double | `3.14` | Floating-point values |
| Decimal128 | `NumberDecimal("19.99")` | Exact decimal quantities |
| Date | `ISODate("2026-10-17T00:00:00Z")` | Timestamps |
| ObjectId | `ObjectId()` | Common document identifiers |
| Array | `["JS", "Node"]` | Lists |
| Embedded document | `{ city: "Patna" }` | Related nested fields |
| Null | `null` | Explicitly missing value |
| Binary | `BinData(...)` | Binary data |

The shell's default numeric representation depends on values and context; use explicit constructors when a specific BSON type matters.

## 3. What is ObjectId?
An ObjectId is a **12-byte BSON value**, commonly displayed as **24 hexadecimal characters**:
```js
const id = ObjectId()
print(id)
db.users.insertOne({ _id: id, name: "Asha" })
db.users.findOne({ _id: id })
```
It includes a timestamp component, a random value, and a counter. ObjectIds are generally generated by drivers and are designed to be highly likely unique; they are **not** a security secret or a guaranteed chronological ordering across all machines.

**Important:** `ObjectId("507f1f77bcf86cd799439011")` is not the same BSON type as the string `"507f1f77bcf86cd799439011"`. Queries must use the correct type.

## 4. Practical example
```js
use learningDB
db.payments.insertOne({
  customer: "Ravi",
  amount: NumberDecimal("501.25"),
  paid: true,
  createdAt: new Date(),
  tags: ["wedding", "gift"],
  address: { village: "Example Village" },
  note: null
})
db.payments.findOne({ customer: "Ravi" })
```
Why Decimal128? Decimal arithmetic avoids common binary floating-point representation problems. Your application must still handle conversions and rounding rules deliberately.

## 5. Node.js / Mongoose connection
Mongoose `Schema.Types.ObjectId` declares a reference-like field type, while MongoDB stores the actual BSON ObjectId value. JavaScript `Date` values serialize as BSON Date. Mongoose schema types are application modeling rules, not new BSON storage types.

## 6. Common mistakes
- Comparing an ObjectId to a string without conversion.
- Assuming ObjectId reveals an exact trusted creation timestamp.
- Using floating-point numbers for money without a precision strategy.
- Confusing JavaScript `undefined`, missing fields, and BSON `null`.
- Assuming BSON allows unlimited document size (16 MiB maximum).

## Practice
Insert a document with an ObjectId, Date, Decimal128, nested address, and array. Retrieve it using the exact `_id` type.
